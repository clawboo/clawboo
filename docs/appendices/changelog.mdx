The full notes for every release are in [`apps/cli/CHANGELOG.md`](https://github.com/clawboo/clawboo/blob/main/apps/cli/CHANGELOG.md), and [Release process](/internals/release-process) explains how a release is made.

<Note>

These docs follow the main branch, which is ahead of the latest npm release, 0.5.0. What is listed under **Unreleased** is not in 0.5.0 yet. Run `clawboo --version` to see your version, and `npx clawboo@latest` to run the latest release.

</Note>

<Update label="Unreleased" description="On main, not yet on npm">

The next release gives a team chat rooms, lets you steer a task while an agent works on it, and rebuilds the workspace around a team. The Board opens on a calmer Kanban view. Clawboo Native runs on a local Ollama with no key, and a security gap for installs behind a reverse proxy is closed.

**Security**

- **The access token covers the MCP servers behind a proxy.** On 0.5.0 and older, any request from `127.0.0.1` reached `/api/mcp/` without the access cookie, so a reverse proxy on the same machine exposed the MCP servers and let anyone ask `/api/mcp/config` for a signed attach URL. Now a request without the cookie reaches an MCP server only with an attach token, only on a direct connection to `127.0.0.1`, and never through a proxy. `/api/mcp/config` always needs the cookie. Until you upgrade, deny all of `/api/mcp/` at the proxy: see [Security model](/operating/security).
- **Re-copy attach URLs you set up by hand.** If you attached an agent by URL on an install with an access token, copy the URL again from `GET /api/mcp/config` (sending the access cookie). The old URL carries no token and gets a `401`.
- **A token the access check cannot use stops the server.** A `STUDIO_ACCESS_TOKEN` with a character other than letters, digits, `.`, `_`, `~` and `-`, such as `openssl rand -base64` output, used to turn the check off. Now the server logs `SECURITY: refusing to start` and exits; make a new token with `openssl rand -hex 24`. Files that hold keys or tokens, including `clawboo backup` files, are now readable only by you.
- **Claude Code agents leave your own Claude Code setup out.** They no longer load your `~/.claude` settings, plugins, hooks, MCP servers, `CLAUDE.md` and rules, or Claude Code's auto memory. A repository's own `CLAUDE.md` and `.claude/settings.json` still apply. Auth you set in `~/.claude/settings.json`, such as an `env` block or an `apiKeyHelper`, no longer reaches agents: set those variables in the environment you start Clawboo with. See [Claude Code](/runtimes/claude-code#your-own-claude-code-setup-stays-out).
- **Connector access set to ask every time always asks.** A remembered **Always** used to skip the prompt even under `approvalPolicy: always`. Now the call asks, and the card offers no way to remember it.
- **Risky hand-offs are never remembered.** An `allow_always` answer sent through the API used to stop that leader's risky hand-offs from asking again, with no end date and no way to undo it in the dashboard. Now it allows that one hand-off.
- **Attach URLs name real teams, and their secret can be replaced.** `GET /api/mcp/config` refuses a `scopeTeamId` that names no team, and a Clawboo agent signed for a team it is not on. `POST /api/mcp/attach-secret/rotate` replaces the secret behind every attach URL without a restart. See [MCP servers](/operating/mcp-servers#the-attach-token).
- **TeamChat takes no author from tool arguments over HTTP.** A session without a signed room-and-author binding gets no TeamChat tools.
- **`create_subtask` checks the team.** A parent task from another team is refused.
- **Images in an agent's text no longer load on their own.** In chat, a task's report and its comments, an image used to load from its address as soon as it was shown, so an agent steered by something it read could send data out in that address. It now shows as a link named after its alt text that opens only when you click it. An address that is not a web or same-site one is only named.
- **API routes match letter case exactly**, and with no access token set, the server logs a one-time `SECURITY:` warning when a request arrives through a reverse proxy.

**Rooms and chat**

- **Rooms.** Next to the team's own chat, now called **General**, a team can have rooms, each with some of its members. A room has its own conversation, task cards and graph. Boo Zero leads every room, and the team's rules, brief, memory and board stay team-wide. Create one with **New room**, and pin, rename or delete it from its menu. Deleting a room archives it. See [Team chat](/using/team-chat).
- **Chat with Claude Code, Codex and Hermes agents.** The chat on their page now runs on the Clawboo server, with no OpenClaw Gateway, and each agent keeps its conversation from one message to the next until you send `/reset`. These chats and Clawboo Native's start in the agent's team folder, where a Clawboo Native agent can now use its file tools and, with **Let this Boo ask to run commands** on, ask to run a command. See [Agents](/using/agents#chat-with-an-agent).
- **Clear chat.** Every chat's menu can clear it. The messages are set aside rather than deleted, the agents start that conversation fresh (OpenClaw agents are sent `/reset`), and the chat stops showing task cards from before the clear. Those stay on the Board and in the **Tasks** card.

**Steering**

- **Steer a running task.** Comment on a task from a team chat's **Tasks** card, or from **Tasks & Routines** on an agent's page, and the agent reads the comment during the run. Clawboo Native, Claude Code, Codex and OpenClaw take it at the run's next step; Hermes pauses the run and resumes the same session with your comment. The comment always lands in the agent's mailbox as well, so a task that is not running yet still gets it. See [Steering a running task](/runtimes/index#steering-a-running-task).
- **Codex runs in `codex app-server`**, which is what lets it be steered. An older Codex without it falls back to `codex exec`, where a comment waits for the next run.
- **A reply reaches the agent, and says where it went.** A reply on a task now goes to the agent it belongs to whatever the task's status, including a task moved back to To do. A reply to a task waiting on you, or waiting in To do, starts the agent on it again, so answering a blocker no longer needs a second click on **Retry**; replies within 15 seconds start one run. A reply to a task in review waits for the agent to read after the check. A finished task cannot run again, so the reply is not sent, and the note under it offers **Send as a follow-up task**, a new task for the same agent. The Board's task drawer now has a reply box, and a note under each reply you send, there and in the chat's **Tasks** card, says where it went. The **Tasks** card's **Send and retry** button is gone, since **Send** does both. See [Steer a running task](/using/board#steer-a-running-task).

**The workspace**

- **A sidebar you can resize and hide.** Drag the agent column's edge to resize it, or hide it with `Cmd/Ctrl + \`. The nav reads **Home**, **Org chart** (the new name for Atlas), **Board**, **Connectors**, **Memory**, **Marketplace** and **Settings**, and `Cmd/Ctrl + 1` to `4` open Org chart, Board, Connectors and Memory. **Fleet** moves to **Settings** > **Insights**.
- **Cards beside every chat.** An agent's page shows **Graph**, **Tasks & Routines**, **Browser**, **Activity** and **Details** next to its chat. A team chat shows **Browser**, the team's or room's graph, **Tasks** and **Activity**.
- **Home.** Each team has a Home page, the place its dashboards and its agents' artifacts will live.
- **The Org chart turns.** With the browser panel open, the radial Org chart turns around Boo Zero to bring the team you pick next to the panel.

**Ollama and providers**

- **Ollama with no key.** Picking **Ollama** during setup now counts as a connected provider everywhere: agents deployed without a model pick run on it, Boo Zero is created on it, and team chat and one-to-one chat both work. Turn it on or off in **Settings** > **Runtimes** > **Clawboo Native** > **Manage**.
- **Your pulled models.** The model lists show the chat models your Ollama has pulled, mark the ones that cannot use tools, and show `ollama pull llama3.2` with **Check again** when none is pulled.
- **Your default provider wins.** Agents deployed without a model pick run on the provider you chose as your default, instead of the first one with a key.
- **OpenClaw on Ollama.** When Ollama is your provider, **Set up OpenClaw** configures OpenClaw on it instead of asking for a key, and stops with the `ollama pull` command when the model is missing. Setup also connects to the Gateway port in your OpenClaw config.

**The Board**

- **Kanban first.** The Board opens on **Kanban** (the view called All before, key **K**), every task by status with Needs you first. **Today**, **Week** and **Month** stay as the calendar views, and a view you already picked is kept. On Kanban, cards say how long ago they were added or finished ("4m ago", "Yesterday", "3d ago"); the calendar views keep clock times.
- **One header and one toolbar.** The header holds the title, the team filter, **Star** and **New task** (key **C**). **Refresh** and the subtitle are gone; a spinner shows only when a background read is slow. The toolbar holds **Find** (**/** or **Cmd/Ctrl+K**), **Filter** (agents, tasks with no agent, what is running now), **Display** (routine runs, the Cancelled column, cost and time on cards), an agents-working chip and the view menu. "Since you last looked" is a chip that shows only when something changed.
- **Calmer cards.** Cards and lanes are neutral, with color only in each column's status mark and amber for Needs you. Cards drop the runtime mark, the corner clip and the hover lift, and counts no longer roll.
- **New task in one sentence.** Write what should get done and press Enter. Clawboo suggests who should do it by matching your words to each agent's name and the role in its SOUL.md, else the agent you last gave a task to, then the team lead, and says why. Picking an agent also picks its team. **More options** opens the full form with Team, Agent and Details.
- **Needs you cards lead with one action.** Each card says why it waits and offers **Retry**, **Assign**, **Review** or **Open**, with the other choices, including **Dismiss**, in a **More** menu.
- **The task drawer reads like a document.** The agent's report once, as formatted text, then the brief, the properties, verification, the workspace, run history, comments and activity. Each section folds from its heading, empty ones are not shown, and **J** and **K** step through the column. See [Board](/using/board).

**Budgets**

- **Pick a budget by name.** In **Settings** > **Insights** > **Governance**, choose agent, team or mission, then the agent, team or board task from a list you can search. You no longer look up an id first, and each budget shows its name. The form no longer offers tenant, which nothing charges; a tenant budget you already have still shows.

**Fixes**

- Creating and deleting agents works without an OpenClaw Gateway, and a new agent made on the Org chart always joins a team.
- An OpenClaw agent deleted while its Gateway is down stays deleted.
- Approving this device during OpenClaw setup shows what went wrong, with **Retry**, instead of sticking on "Approved. Reconnecting…".
- Updating from the dashboard keeps working after the first update, a failed update shows npm's own reason, and Clawboo runs `openclaw doctor --fix --non-interactive` once when a newer OpenClaw needs it before the Gateway will start.
- The Org chart's Radial layout spaces each team's Boos apart, also with "reduce motion" turned on.
- While one of a routine's runs is still going, the Board's calendar marks the right next run.
- Loading the dashboard no longer counts against the API's request limit.
- A Boo no longer loses its body when another copy of it is hidden.
- An agent can no longer put a card back after you moved it: its own status changes are refused, with a message telling it not to try again, until the task runs again.
- The Kanban lanes run unbroken to the bottom, and dropdown menus are as wide as their longest option.
- Team chat runs, and task runs that only read (routines made in the dashboard included), start in a folder of their team, `~/.clawboo/workspaces/<team id>`, instead of the folder that holds Clawboo's database and keys. The folder only sets where Claude Code, Codex and Hermes start: they keep full access to your files. Clawboo Native agents get their file tools there, kept inside the folder. An agent's **Workspace** tab shows the folder, and deleting a team deletes it with its files. See [What agents can do](/concepts/permissions).
- A model your own Ollama serves is recorded at $0 and reads **free**, a Claude Code or Codex run whose final cost report crosses a hard cap keeps its result (the next run is refused instead), every run that ended without a cost report is estimated, and **Tokens Used** lists every runtime. See [Budgets and spend](/using/budgets-and-spend).
- A paused hard cap now refuses new team-chat and one-to-one chat turns before they start, with a notice in the chat saying which budget is paused; a refused hand-off waits in **Needs you** with the reason. Saving a budget again keeps its mode unless you pick another, and the Governance form shows the mode of a budget you already have. See [What a hard cap stops](/using/budgets-and-spend#what-a-hard-cap-stops).

</Update>

<Update label="0.5.0" description="2026-10-21">

The Board becomes a calendar and a task board at once, moving a card by hand does what it says, and a task's cost counts every run. See [Board](/using/board).

**The Board**

- **Days as rows.** Status columns run across the top and days run down the side. Week is the default; Today, Month and All are a click away, or **D**, **W**, **M** and **A**. Open work sits on the day it was added, and work that reaches Done or Cancelled moves to the day it finished. Open work from before the range gathers in an Earlier row, and empty days fold into a thin line you can open.
- **Needs you lives in today.** Approvals and stuck tasks sit in today's row with **Retry**, **Assign** and **Dismiss**, and tasks that broke the same way share one card.
- **Routines on their days.** Each routine's upcoming runs show in To do on the days they are scheduled, from the new `GET /api/schedules/occurrences`. A **Routines** switch hides them.
- **Since you last looked, and Find.** A line under the title says what changed while you were away, and changed cards carry a dot until you look. **/** finds any task or routine.
- **Calmer cards.** One detail row: the agent, its runtime, one status mark or the cost, and when the card was added or finished. Unassigned work no longer claims to run on OpenClaw.

**Moving cards by hand**

- A drop goes to the column under the pointer and nowhere else.
- In progress takes no card by hand, because moving it there started nothing. A card left there shows in Needs you as **Not started**.
- Finishing a card asks which day it finished when it sits on another day, and the board `PATCH` takes a `completedAt`. Cancelling always asks first, and cancels the plan steps that were waiting on it.
- Moving a card an agent is working on stops that run, its late result can no longer override you, and whoever delegated the task is told.

**Also in this release**

- **Task costs that count every run.** A task's cost is the sum of every run, failed ones included. A run with no reported charge is priced from its token usage, or from its prompt and reply length when there is none, and marked as an estimate.
- **A quieter team chat.** A teammate's reply reaches the chat only when you addressed it or it is the lead's summary, and **Stop** also stops a run that was about to start.
- **Routing by role.** On the lead's turn the roster lists each teammate's runtime and a one-line role from its SOUL.md, so Boo Zero routes work by what a teammate does.

</Update>

<Update label="0.4.0" description="2026-09-28">

Agents reach outside apps through connectors, team memory becomes a graph that learns, the Scheduler becomes Routines, and the Board gains a Needs you column.

**Connectors**

- **A Connectors view in the sidebar.** Curated connectors Clawboo runs itself, a longer list from the official MCP registry, and Gmail, Slack, Jira and more through Composio. Turning one on is one button, and sharing it with an agent is a line on the graph that is also the permission Clawboo enforces. See [Connectors](/using/connectors).

**The graph**

- **Build on the graph.** Every Boo carries one visible port. Pull a thread onto another Boo to connect them, or let go on empty canvas to pick a skill, a connector or a new agent, already wired. Routes, skills and shares all come off the same way, and a share has an Undo. See [Org chart and team graphs](/using/org-chart).

**Memory**

- **Team memory is a graph that learns.** Memory is a sidebar view where facts cluster and link by similarity. Agents report whether a recalled fact helped, so a fact two teammates found useful comes first, and one that misled someone leaves automatic recall. Every recalled line carries an id the agent can cite. See [Memory](/using/memory).

**Work**

- **Routines.** The Scheduler is now Routines, and a routine targets a team or one agent. A team routine posts its instructions into the team chat for the lead; an agent routine files a task for that agent. See [Routines](/using/routines).
- **Needs you, and tasks for one agent.** The Board gains a Needs you column for approvals and stuck tasks, with **Retry**, **Assign** and **Dismiss**. **New task** asks for a team, then an agent, and only that agent works on it.

**Platform**

- **The catalog leaves the package.** The agent and team catalog is downloaded instead of bundled, and grew to nineteen packs, each naming its source repository, commit and license.
- **OpenClaw 2026.9.** The Gateway pin moves from `~2026.5` to `~2026.9`, with the fixes that line needed.
- **Served under a path.** `CLAWBOO_BASE_PATH` mounts the whole app under a URL prefix behind a reverse proxy.
- **In-place database upgrades.** An upgrade adds new columns to an existing `clawboo.db` instead of failing on first use.
- **Coordination that stays awake.** Task changes reach running agents through a per-agent mailbox, runs prove they are alive with regular heartbeats, and a team-chat run that ends without an answer says why.

**Removed and limits**

- `POST /api/onboarding/seed-native-team` is removed. Deploy a team from the Marketplace, or with `POST /api/teams`.
- The API has request rate limits, with a much lower one on the costliest routes, such as installing a runtime, driving the Gateway, signing in a CLI and approving a device. See [Limits and defaults](/reference/limits-and-defaults).
- The Tasks MCP server caps task creation: 24 live subtasks per parent, 2 levels of nesting, and 30 top-level tasks per rolling 5 minutes.
- A task dependency that would form a cycle is refused.

</Update>

<Update label="0.3.1" description="2026-07-20">

A patch for running Clawboo Native teams day to day: team-chat replies stay put, status badges update live, and each runtime manages its own providers.

**Team chat**

- **Replies stay in the transcript.** Every streamed team-chat reply is saved or cleanly cleared, so a delegating agent's message cannot vanish on the next update or on reload. A Clawboo Native one-to-one reply that fails mid-stream is kept.
- **Live Working and Idle badges.** The status marks in the sidebar and in team chat update in real time for Clawboo Native and server-run team work, not only for OpenClaw.

**Providers and models**

- **A provider manager per runtime.** **Manage** on Clawboo Native, OpenClaw and Hermes in the Runtimes panel lists the providers you connected, each with connect, disconnect and reconnect, plus a default-model picker for Clawboo Native. A Clawboo Native runtime with no key reads **Disconnected**, with a shortcut to set it up.
- **Reconnect with any provider.** Reconnecting Clawboo Native works with any provider you already set up, not only Anthropic.
- **Provider first, then model.** Creating a team asks for a provider (only the connected ones), then its model, and shows the exact default model that will run.

**Polish**

- The **Add runtimes** step of setup shows your connected providers read-only, with **Back** to the step where you add keys.
- The sidebar mascot's tooltip reads "Boo Zero", matching what clicking it opens.

</Update>

<Update label="0.3.0" description="2026-07-15">

Native-first: the first run needs one provider key and nothing else. No OpenClaw install, no Gateway and no other CLI. OpenClaw, Claude Code, Codex and Hermes become runtimes you add to a setup that already works.

**Setup and providers**

- **Setup starts with a key.** Connect a provider, optionally add runtimes, then deploy a real team from the Marketplace. See [Quickstart](/getting-started/quickstart).
- **A Providers hub in Settings** covers ten providers. Pasting a key fetches that provider's live model list, so the model picker offers what your key can reach.
- **A first-run tour**: a one-time, skippable spotlight over the sidebar. See [Tour the dashboard](/getting-started/dashboard-tour).

**Teams and chat**

- **A runtime and a model for each member.** Creating a team gives every member, the lead included, its own runtime and, where the runtime uses one, its own model. A choice that is not available falls back to Clawboo Native instead of blocking the deploy. See [Mix runtimes on one team](/guides/multi-runtime-team).
- **Clawboo Native teams chat and delegate.** A Clawboo Native team sends from team chat and streams back, and its lead hands work to teammates the way an OpenClaw lead does. See [Work with your team in chat](/using/team-chat).
- **Orchestration runs on the server**, per team, so delegated work carries on after you close the tab.
- Failed and abandoned delegations show on the Board instead of leaving the delegating agent waiting.

**The graph**

- Every Boo carries its runtime's mark and shows its model when expanded, and an agent's MCP servers appear as tiles beside its skills. See [Org chart and team graphs](/using/org-chart).

**Resilience and security**

- **A degraded Gateway no longer blocks the dashboard** when you have other agents. A banner offers the recovery that applies: restart the Gateway, approve this device, or retry.
- Hermes installs on Python 3.11 or newer instead of failing on an older system Python, and an existing `codex login` is recognized.
- Binding to a non-loopback address refuses to start without an access token.

</Update>

<Update label="0.2.0" description="2026-06-20">

Clawboo becomes an orchestrator for several agent runtimes instead of a control panel for OpenClaw. Clawboo Native agents are built in: paste a provider key and start. OpenClaw, Claude Code, Codex and Hermes join as teammates in one chat, sharing one board and one memory.

- **Five runtimes** behind one adapter: Clawboo Native, OpenClaw, Claude Code, Codex and Hermes. See [Choose a runtime](/runtimes/index).
- **A durable task board** that agents claim work from, replacing delegation parsed out of chat text. See [The board](/concepts/the-board).
- **Four MCP servers**, Tasks, Memory, Tools and TeamChat, that give any attached agent the board, team memory, tools and team chat. See [MCP tools reference](/reference/mcp-tools).
- **Verification**: fixed checks plus an independent critic agent review some task results before they count as done. See [How work is checked](/concepts/verification).
- **Guardrails**: USD budgets, tool-loop breakers, limits on delegation depth and fan-out, and an audit log. See [Budgets and guardrails](/concepts/governance).
- **Observability**: an append-only event log, traces and an error taxonomy. See [Observability](/concepts/observability).
- **Its own home** in `~/.clawboo/`: the database, settings, an encrypted key vault, and a folder per runtime and agent.
- **A team-task scheduler**, which later became Routines.
- **A release security audit**, and a loopback-only bind by default.

**Removed**: the delegation engine that parsed chat text, the experimental Labs UI, and the per-feature flags.

**Upgrading**: in 0.2.0 a database schema change meant resetting the database, and a 0.1.x database could not be upgraded in place. Since 0.4.0 an upgrade adds missing columns in place. See [Data and state](/operating/data-and-state).

</Update>

<Update label="0.1.1" description="2026-05-19">
