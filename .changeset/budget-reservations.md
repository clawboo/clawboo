Runs that start at the same time no longer take a hard-cap budget past its limit together. Each run now holds its estimated cost on every budget it counts toward from the moment it is let start until it ends: task and API runs, agent routines, team chat, one-to-one chat and peer exchanges. On a nearly spent hard cap, a run that would go beside others starts only if the spend, what they hold and its own estimate fit under the limit; otherwise it is refused with "The <scope> budget is close to its hard cap, and runs already going have set aside the rest of it, so this run did not start." Each run is checked again right before it calls the model, its real cost replaces the estimate as it is recorded, and its hold goes when it ends, however it ends. Holds left by a server that stopped mid-run are dropped at the next start. The estimate is the most one of the agent's last ten runs cost, or 50 cents for a new agent, so a run can still cost more than it held. A run going alone and every warn-only budget, the default, behave as before. Usage on a model with no known price is held and charged at the default rate and follows the budget's mode. A task run refused this way answers `422` with `budget_held`, and an agent routine refused this way keeps its schedule.

One-to-one chat with a Clawboo Native, Claude Code, Codex or Hermes agent now shows in **Tokens Used**: every turn that calls a model writes the same cost record a team-chat run does, from the runtime's own figures where it gives them and estimated from the text where it does not, whether or not the agent has a budget.
