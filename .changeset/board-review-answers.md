'clawboo': patch
---

Fixes to the Inbox and the Board. **Mark seen** on the Board now marks read only the cards it is showing, so a card a filter or the date range hides stays unread in your Inbox. **Mark all read** waits until the team you picked has loaded, so it can no longer clear that team's tasks from the last team's list. In a task opened from **Needs you**, J and K step through **Needs you** rather than every task, and on **Unread** you can step back to a task you just read. Cancelling a task no longer brings the later steps it cancels back to you as unread, and neither does a run that archiving a chat room stops. Archiving a room now updates an open Inbox straight away. The Inbox badge also recovers by itself when a read hangs, and when the server comes back after being away. On a **Waiting for your OK** card, a task that also failed its check now says so and keeps **Review**, and **Always allow in this team** now means the team of the task the card is on. In a task's drawer, a teammate's comment now sits in **Comments** under their name rather than in the worker's report. If a team's setting for agents waking each other cannot be read, the switch says so and offers a retry. A comment a teammate left for a task that then finished no longer reaches that agent's next run. A comment written just before an agent asked its question no longer closes that question and starts the task when the two land in the same millisecond or the clock steps back, and one written just after now always does. After a crash, if Clawboo cannot yet tell whether a leftover agent process is its own, it now keeps the record and stops that process at a later start, rather than forgetting it.

How a failure is named now agrees with what the run history files it under. A limit over a time window, such as "too many request tokens for this hour", counts as a rate limit, so a routine keeps its schedule through it instead of stopping. A failure that says only "too many tokens", or that names a quota or a usage limit, no longer tells you to change context-window settings: you see the reason it gave. A Hermes reply that opens with its own warning about the scanner keeps that line. **Mine** on the Board and in the Inbox fills in by itself when reading who you are failed the first time.

Fixes to hand-offs from Boo Zero's chat. A hand-off now starts when the reply first mentions the syntax in code, and one on the line straight after a quote, or partway through a quoted sentence, is treated as shown rather than started. If one hand-off in a reply can be read and another cannot, the first starts and the chat says the other did not. Its card reads **Handing off to** while the reply is still being written, since nothing has started yet. A result Boo Zero reads no longer closes its request before the reply's hand-offs are decided, Stop ends the hand-offs a reply had not got to, and a result kept since a Stop stays out of your next message while a pause covers its team. A long-running chat still counts its old open work, several long results in one update are each cut to fit, and an @Team works whenever the server says this chat can hand off.
