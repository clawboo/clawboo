A team-chat work check now waits while a teammate is still working in the team folder, so it no longer runs in the middle of a change a teammate is making, which could fail the check and send the fix note to the wrong agent. It waits for other runs of the team in any room, in a 1:1 chat and on the task runner when the run has no worktree, and for another task's check, so two tasks that finish together are checked one after the other. The card reads **Waiting to check**, and a comment says who it is waiting for. After 15 minutes the check runs anyway and says so in a comment and in its result. A waiting check takes no run slot and no budget and never delays a teammate's start. A person's move or **Stop** ends the wait. **Stop** puts the task back in **To do** with the agent's report kept, and a restart hands the task to a person and tells whoever handed it out. Saving the folder now tries again when a file disappears as it is read, so a busy folder no longer lets finished work reach **Done** unchecked. This does not keep teammates' work apart: what a teammate changes while a task runs is still part of that task's measured change, and a run that starts after a check began can still change the folder under it.
