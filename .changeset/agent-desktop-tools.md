On Linux, **Install the desktop tools** on an agent's **Screen** view installs the programs that give each agent a screen of its own into Clawboo's runtimes folder: TigerVNC's own Linux build of `Xvnc` 1.16.2 (x86_64) and Cua Driver 0.38.0 (x86_64 and arm64), each checked against a SHA-256 Clawboo pins as it downloads and before it is unpacked, and switched to only when everything worked. TigerVNC is GPL-2.0 and runs as a separate program; Cua Driver is MIT. An `Xvnc` from your distribution is still used first, and then no TigerVNC is downloaded. The offer appears only where it helps: on arm64, where TigerVNC publishes no build, the view says to install `Xvnc` with the package manager, and **Install Cua Driver** adds the driver alone once agents have a screen. Clawboo's copy of TigerVNC needs some system libraries and the system's keyboard compiler, which Clawboo does not install (on Debian and Ubuntu: `libxcvt0`, `libxshmfence1`, `libgbm1`, `x11-xkb-utils`, `xkb-data`), so when a display cannot start, the **Screen** view and `GET /api/agents/:agentId/computer` (`displays.problem`) name the missing file and, on Debian or Ubuntu, its package. New route: `POST /api/computer/tools/install` (a person's act, sensitive rate tier; a second request joins the install already running).
