---
'clawboo': minor
---

Clawboo now connects to the OpenClaw Gateway only once something needs it: an OpenClaw agent (or a delete of one still owed to the Gateway), opening OpenClaw in **Settings > Runtimes** (or starting the Gateway from Clawboo), or a routine for an OpenClaw agent falling due. An install with OpenClaw agents connects at every start, as before. Until then neither the server, the dashboard nor `clawboo` connects to the Gateway or probes its port, so a Gateway that a service manager starts on its first connection, such as a systemd socket unit on a small Linux machine, stays asleep instead of starting at every boot. A Gateway nothing uses is reported as not in use rather than unreachable: OpenClaw's row reads **Not in use** with **Connect**, the welcome screen offers **Open OpenClaw** to bring in the agents of an OpenClaw already set up, **Capabilities** shows no warning for it, System Health passes its Gateway check as "not in use yet", the dashboard loads with no offline banner, `GET /api/agents` is not `stale`, `GET /api/agents/registry/health` and `GET /api/system/status` report `inUse: false`, and `GET /api/system/idle` reports the Gateway's cron jobs `off` with the reason `not_in_use`. New route: `POST /api/agents/registry/connect`, which the dashboard sends when OpenClaw's row opens; the registry health also reports `configured`. With a Gateway set up that nothing used yet, creating an OpenClaw agent or a sync without a body over the API now waits up to about 5 seconds for the connection. A browser connection to the Gateway that fails no longer keeps retrying unseen. A reconnect asked for while a connection was still being made no longer leaves the server unable to connect until it restarts. `clawboo` no longer prints whether a Gateway answers on port 18789 when it starts.
