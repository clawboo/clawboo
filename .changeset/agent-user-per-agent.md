'clawboo': minor
---

On Linux, each agent can now run as an operating system user of its own, so agents are walled off from each other as well as from Clawboo. Set `CLAWBOO_AGENT_USERS` to a pool of users you create once (names, or a uid range such as `uid:20001-20008`), `CLAWBOO_AGENT_GROUPS` to a pool of team groups, and `CLAWBOO_WORK_DIR` to a folder of your own. It is used instead of `CLAWBOO_AGENT_USER`, never with it, and is off unless you set it.

An agent gets the next free user when it is created, oldest first, and keeps it for its life; each team gets a group the same way. Each agent user has an agent host of its own, started on the agent's first need, closed with the agent's processes after 10 minutes with nothing to do, and watched on its own: a host that stops answering costs only its own agent's processes. An agent's runtime homes, browser profile and display live in its own user's home, so one agent cannot read another's sign-ins, sessions or cookies, reach its display, or signal its processes. A team's folders are yours, with the team's group, mode `2770` and an inherited ACL, so teammates read and change each other's files and nobody else reaches them; an agent with no team gets a folder of its own. A deleted agent's processes stop at once, and its user is wiped (its home, its temporary files, each checked afterwards) before another agent gets it; a deleted team's folders are removed, and no process may still hold its group, before the group is handed out again. Moving an agent to another team stops its processes, which start again with the new group. A check of an agent's work runs as that agent, never as another teammate, and the agent host refuses a file of a team's folder that a link leads out of the folder. Teammates still reach each other through what they leave in their shared folder. With no free user, a new agent is still created and its runs say why they cannot start; it never falls back to a shared user.

The startup check now also refuses a pool whose users share a uid, a primary group or a home, an agent user that is a member of another's group or of a team group, a server user missing from a group it makes folders for, a missing `setfacl`, and any agent user that can list another's home or signal another's process, each proven from inside that user's own host. `clawboo agent-user plan --pool <n> --teams <m>` prints the setup, with the one sudoers rule a pool needs (the users written out one by one: sudo takes a team group only then), and `clawboo agent-user check` checks a pool too.

Not available yet with a user per agent: code tasks that work in a checkout of a repository (refused with the reason), Hermes (its gateway runs every Hermes agent's tools in one process, so it does not start), OpenClaw (not covered, as before), connectors with local reach shared by every agent (they do not start; each agent's own browser does), picking an agent for a Codex or Hermes sign-in on the Runtimes page (give the runtime an API key), a container launcher for a pool, macOS, and copying older agent state in.
