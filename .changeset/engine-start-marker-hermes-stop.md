'clawboo': minor

When Clawboo stops, the Hermes gateway now gets its planned stop: SIGINT to the gateway process, up to `CLAWBOO_HERMES_STOP_GRACE_MS` (5 seconds by default, at most 8) to exit, then it and its processes are killed. It used to get SIGTERM, which Hermes takes for a crash. Clawboo waits for it at the same time as its other runtime processes, so a stop takes about 9 seconds at most, and a server that never started the gateway waits for nothing.

The server also writes a start marker, `api-port.json`, next to `api-port.txt`. It names the server's process (pid, start time, boot time and, on Linux, PID namespace) and version, so a reader can tell a running server from the record of one that crashed, whose port another program may hold by now. `api-port.txt` is unchanged. The `clawboo` command checks the marker before it trusts the recorded port: a port whose marker shows its server is gone gets no access token and no longer counts as a busy server holding the port. With no marker, or one it cannot check, it uses `api-port.txt` as before. The fields are described in the configuration reference.

A stop asked for while the server is still starting now behaves the same however it arrives. A SIGINT or SIGTERM sent during the start is kept, as the shutdown message already was, and runs once the server has started. A kept stop now runs before anything the server starts once it listens, so on a start that moves work folders, the routines no longer resume (and could start a run) in the moment before the stop. A SIGTERM during the start used to be taken by one part of the server that happened to listen for it, so the server kept running and its later stop left the OpenClaw connection open. The server's parts (the routines, the approval reaper, the MCP supervisor, the OpenClaw connection and the trace exporter) no longer listen for signals themselves; the stop stops each of them, and the whole stop stays under about 9 seconds.
