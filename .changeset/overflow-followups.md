'clawboo': patch
---

A one-to-one chat no longer resumes a session that outgrew the model's context window. On Claude Code, Codex and Hermes the next message starts fresh, and one notice in the chat says the agent is no longer carrying the conversation, or that the turn was too large if it was the conversation's first. Clawboo Native keeps the session while trimming its oldest turns can make real room, and says so, and drops it, with the same notice, when trimming could not. It also drops it, giving the provider's reason, when a provider refuses a resumed turn in words Clawboo does not recognize and sending the conversation again could only fail the same way. Team chat now says when an agent's session was dropped this way, and such a turn no longer shows advice about a wrong context-window setting, which stays for OpenClaw. Hermes and Codex on `codex exec` now report a context overflow as `context_overflow`, so a board task on them starts fresh on its next run too. A failed quiet Hermes run gives its reason instead of its session id or a startup warning, and an overflow Hermes recovered from, or one a sub-agent hit, no longer reads as the cause of a later failure. Claude Code's `blocking_limit` and `rapid_refill_breaker` endings now count as out of room, like `prompt_too_long`, and Claude Code's own text for these endings no longer appears as the agent's reply in team chat: it goes on the board as the failure's detail. A rate limit whose message says "too many tokens" is no longer read as a context overflow on Clawboo Native or `codex exec`: it shows its own reason and counts as a rate limit. A resumed run that hits a rate limit or an overload now keeps its session on every runtime, in one-to-one chat and team chat. A context overflow is now always filed as one, even when a token count in its message looks like a status code. A chat notice written in the same millisecond as the reply before it no longer disappears from the chat.
